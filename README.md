# Leadly

Windows-приложение (Electron + React + TypeScript + SQLite): поиск локального бизнеса без сайта.

## Установка

1. Скачайте `leadly-<версия>-setup.exe` (из артефакта сборки, см. «Сборка .exe») и запустите. Установка в один клик, без прав администратора, ярлык появится на рабочем столе.
2. Windows может показать предупреждение SmartScreen («Windows защитила ваш компьютер»). Причина: у программы пока нет сертификата подписи кода. Нажмите «Подробнее», затем «Выполнить в любом случае».
3. Удаление: «Параметры» → «Приложения» → «Установка и удаление программ».

## Первый запуск

Онбординг попросит ключи:

- Anthropic API: обязателен (оценка, аудит, сообщения). Создаётся на console.anthropic.com → API Keys.
- Google Places API: необязателен, даёт дополнительный источник. Ключ создаётся в Google Cloud Console (включить Places API).
- Telegram-бот: необязателен, для уведомлений. Токен выдаёт @BotFather (`/newbot`).

## Где лежат данные

`%APPDATA%\Leadly`: база, настройки и резервные копии.

## Резервные копии

Копия базы создаётся автоматически раз в день, хранятся последние 7. Ключи в копии не попадают. Разовая копия: «Настройки» → «Экспорт БД».

## Программа сама ничего не отправляет

Сообщения клиентам не уходят автоматически: «Написать» копирует текст в буфер обмена и открывает чат. Отправляете вы сами.

## Разработка

Нужен Node 22 (`.nvmrc`). Команды: `npm install`, `npm run dev`, `npm test`, `npm run build`.

`postinstall` пересобирает нативные модули под Electron (`electron-builder install-app-deps`), нужен компилятор C++.
Без компилятора (например, Linux-машина разработки) `npm install` падает ещё до postinstall: npm сам запускает `node-gyp rebuild` для better-sqlite3 (есть binding.gyp). Тогда:
`npm install --ignore-scripts && node node_modules/electron/install.js && LL_SKIP_NATIVE_REBUILD=1 node scripts/postinstall.mjs`.
`LL_SKIP_NATIVE_REBUILD=1` только пропускает пересборку в postinstall; better-sqlite3 13 поставляется с готовыми N-API-бинарниками, для разработки и тестов этого достаточно.
Для релизной сборки не используйте этот обход: нужен обычный `npm install` на Windows с инструментами сборки.

## Сборка .exe

GitHub Actions, workflow `build-win` (Actions → build-win → Run workflow, либо тег `v*`). Шаги: `npm ci`, пересборка нативных модулей, тесты, `npm run build:win`, проверка упаковки better-sqlite3. Установщик скачивается из артефакта `leadly-setup`.

## Демо-сайты

Для каждого лида можно сделать демо-сайт и QR-открытку (4 на A4). Что нужно:

- GitHub: аккаунт, публичный репозиторий (GitHub Pages на бесплатном тарифе работает только с публичными) и fine-grained токен только на этот репозиторий.
- Cloudflare: аккаунт и токен (счётчик визитов, Worker + D1).
- Ключ Google: необязателен. Без него демо строится на бесплатных данных.

Настройка: «Настройки» → «Демо-сайты». Пошаговая инструкция: «Помощь».

Правовые риски (подробно в «Помощи»): условия Google на отзывы и фото (Maps Platform ToS, п. 3.2.3), авторское право на фото (ГК РФ ст. 1301), публичный репозиторий с телефонами бизнеса (ПДн, 152-ФЗ). Перед «боевым» сайтом замените фото владельца.

От поисковиков страницы демо закрывает только `<meta name="robots" content="noindex">`. `robots.txt` в корне репозитория не действует (у project-site GitHub Pages он не в корне домена), картинки могут попасть в поиск по изображениям.

## Лицензия: как выпустить ключ

Программа требует лицензионный ключ (офлайн, подпись Ed25519). Выпуск:

```
npm run license -- --name "Иван" --days 30
```

`--days` не указан: ключ бессрочный. Скрипт печатает ключ `LEADLY-…`, его отправляют клиенту; клиент вставляет его на экране «Активация».

Приватный ключ лежит вне репозитория: `/home/vibe/claude-workspace/leadly-license/private.pem` (другой путь: `--key` или переменная `LEADLY_LICENSE_KEY`). Сделайте его резервную копию в надёжное место: без него нельзя выпускать ключи, а при утечке любой сможет выпустить ключ сам. Никогда не коммитьте его (`*.pem` в `.gitignore`). Публичный ключ зашит в `src/main/license.ts`; смена пары ключей сделает недействительными все выданные ключи.

## Обновления

Установленная программа сама проверяет GitHub Releases (через 10 секунд после запуска и каждые 6 часов). Чтобы выпустить обновление: `git tag v1.2.3 && git push origin v1.2.3`. Workflow `build-win` берёт версию из тега, собирает установщик и публикует релиз (`.exe`, `.blockmap`, `latest.yml`). У пользователей в «Настройки → Обновления» и в боковой панели появится «Есть обновление»: «Скачать», затем «Перезапустить и обновить». Ручной запуск workflow ничего не публикует.
